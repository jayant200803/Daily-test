Radar values are scaled 0 to 100 where higher is better, for visual comparison only (English TTS).

4. How each number is measured

Time-to-first-audio (TTFA): from sending the text until the first audio is received, with the network round-trip subtracted so it reflects the provider's own speed. Measured from the deployed app, next to the providers.
TTFA = first-audio-byte time − network round-trip
STT streaming latency (time-to-first-word): the audio is streamed to the provider's real-time API and we time the first word returned while audio is still flowing. This is what matters for a live voice agent.
STT sync / batch latency: the whole clip is sent at once; the time is for the complete transcript. These modes cannot return anything until speech ends, so they are shown separately from streaming.
Accuracy (WER / CER): transcript compared to the reference text. English uses WER (words); Japanese uses CER (characters). Higher accuracy is better.
WER = (substitutions + insertions + deletions) ÷ total words
Naturalness: how clean and human the voice sounds, from the Harmonics-to-Noise Ratio (HNR), mapped to 1 to 5. Higher is better.
Naturalness = 1 + HNR ÷ 7.5 (clamped 1 to 5)
Prosody (expressiveness): how much the pitch varies. Flat speech sounds robotic; more variation is more expressive.
Prosody = standard deviation of pitch (Hz)
Speed (RTF) and Robustness: RTF = generation time ÷ audio duration (below 1 is faster than real time). Robustness = accuracy on hard sentences (numbers, currency, symbols, email).

6. Method

Each provider received the identical test set and was measured the same way, at the same time. Latency was measured from the deployed app so it sits close to the providers and matches what the live demo shows; your own latency adds your network distance to the servers, but the ranking holds everywhere. Quality is analysed from the generated audio and does not depend on location. Every value is an average of the measured results; nothing is estimated.

  • Dataset: general, technical, and hard-case sentences (English and Japanese).
  • TTS audio is generated via each provider's streaming API, timed for first audio, then analysed for naturalness, prosody, RTF, and accuracy.
  • STT is measured per type: streaming (first word), sync (whole clip), and batch, on the same clean clip.

7. Summary

  • Atlas STT (streaming) returns the first word fastest and most accurately of the streaming providers, which is what a live voice agent needs.
  • Atlas TTS is the most natural but the slowest to first audio; other providers stream first audio sooner.
  • Sync / batch STT: ElevenLabs and Deepgram return a finished short clip fastest, but cannot respond mid-sentence like streaming does.
